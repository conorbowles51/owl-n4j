# Batch totals after individual statement imports

Investigators could finish a statement through its individual review and still see it counted as unfinished in the batch list. The detailed batch review resolved the saved receipt, but the list only counted its original preparation status.

The list now projects an unambiguous admitted receipt for the same case, evidence version, source hash and statement key. One shared query selects only receipt identity fields across the listed batches. It neither rebuilds OCR proposals nor loads all transactions, changes stored drafts, or submits imports. Duplicate exclusions remain exclusions. Removed, superseded, changed-source and different-period receipts cannot complete an outstanding review through this lookup. Cross-reading overlaps still require the full review; this deliberately does not infer identity from filenames or account labels.

Completed batches can contain saved statements with later review checks, explicit exclusions and assigned sections. The list's unfinished-check count now covers unsaved reviews, rather than historical extraction warnings on already saved statements. Full statement review continues to show current saved-payment reconciliation problems. A completed preparation queue is not a claim that the investigation or every saved-payment check is complete.

Validation: all 43 batch service tests pass, including an individual import with a stale invalid batch draft, current saved reconciliation differences, read-only projection, removal, source-hash changes, statement-key changes, supersession, case isolation and retained duplicate exclusion. The tests load the actual financial router through a package namespace to avoid unrelated optional agent dependencies; the full application bootstrap was not tested by that run. Diff whitespace checks pass. This change is local only; deployed list/detail agreement and realistic live load remain acceptance requirements. Deployment must wait for the normal all-server ingestion gate.
