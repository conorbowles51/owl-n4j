# Financial export acceptance

15 September 2026. This table maps the original evidence-package requirement to the implemented export and its check. It is a finite checklist for the application, not a claim that Loupe can supply missing historical evidence or an expert's opinion.

Use **Findings > Build report** for the investigator's selected observations. Use **Transactions > Reports, balance coverage and verification details** for the transaction/history export and optional tracing review package. These serve different readers; the first explains the investigation, while the second retains the data and calculations needed to check it.

| Requirement | Captured material | Verification and result |
| --- | --- | --- |
| Identify the case and selected scope | `saved-report.json` keeps selected finding IDs/versions. `ledger-snapshot.json` keeps account/date scope and captured readings. Each `scenarios/NN/scenario.json` keeps its own scope. | Same synthetic case, five selected findings, nine current payments and two selected tracing scenarios. Separate scopes are preserved rather than silently combined. |
| Retain original source files | Finding report `statements/` and ledger `source-files/`, indexed by hashes in their manifests. | Three PDFs compare byte for byte with their originals. The receipt and its payment share one source file without duplicate links or a second imported payment. |
| Retain original and corrected readings | Ledger readings retain superseded/current versions and `decisions`; `processing_provenance.statement_import_history` retains original proposals, confirmed imports and digests. | USD 120 original retained, USD 125 replacement current, old reading links to replacement. Three original statement confirmations retained. Working totals are credits USD 1,975 and debits USD 900. Verified totals remain separately identified. |
| Include available custody and decision history | Every export holds `decisions`, `judgement_calls`, `decision_coverage` (each subject's recorded count against the export) and `audit_chain_summary` (the whole chain's count, head and link check). **Include wider case financial review history** adds `case_financial_history`: all case decisions, PDF reviews, custody reports and the audit events themselves, each re-hashed. `expert-support.json` indexes the material and says who or what made each decision. | All recorded financial history for this case captured; 105 audit events verified at capture. Missing earlier custody remains unknown. A recorded report is attributed, not automatically certified. |
| Retain processing and component versions | `versions.components` in `expert-support.json` has one row per statement: text preparation, reader, version, layout, code commit, ruleset and models. Each run stores its components when it starts (`config.components`). A fact history does not hold reads "not recorded". | Original processing manifests and their digests verified. Missing historical manifests stay `not_recorded`; current versions are not substituted for them. |
| Include selected tracing methods, reasons and results | Calculations saved in Findings are in every ledger export (`selected_tracing`: methods, parameters, results, recalculation status). The complete scenarios are in the review package: `scenarios/NN/scenario.json`, `report.html`, `replay.json` and `expert-support.json`. | Single-account and cross-account FIFO rerun from captured inputs. The former leaves USD 220 of the selected deposit; the latter follows USD 80 into savings and leaves USD 220 in checking. Assumptions remain explicit. |
| Include checked receipt/wire observations | Finding report retains `loupe.financial.payment_document/1`, original fields, corrected fields/reasons, document hash, source positions and optional existing-payment link. | The combined report contains the saved receipt, its original PDF and existing-payment reference. Receipt review creates no ledger payment. The separate wire workflow was verified earlier. |
| Attach measured extraction validation | Optional reconciled reader record plus predictions in **Assemble a review package**. `validation/` retains inputs and measurement; support indexes record source-hash overlap and reviewer status. The server setting `FINANCIAL_EXTRACTION_VALIDATION_CORPUS` names a prepared corpus: each ledger export recalculates it and links it only when its labels are independently reviewed. | The software validates and recomputes supplied measurements. The final case package explicitly says validation is unavailable because no independently reviewed real corpus has been supplied. Synthetic checks are not attached as real accuracy evidence. |
| Read and check the result offline | `report.html` for findings; ledger HTML/PDF; `review-index.html` and per-scenario reports for the review package. | Eleven review-package members verified and the package rebuilt identically by `scripts/verify_financial_trace_support.py`. Manifest/member/source checks passed. A second authorised member reopened/downloaded the same finding report. |
| Respect case access | Read permissions for sources, findings and reports; edit permissions for changes; permissions checked again after revocation. | Read-only member could read and download, mutations returned 403, and the same token was denied after membership removal. Temporary account removed. |

Private acceptance files are under `data/local-runtime`: `completion-report.zip`, `completion-ledger-export.zip`, `completion-review-support.zip`, `completion-export-verification.json`, `completion-support-verification.json` and `completion-access.json`. They contain only the synthetic acceptance case but remain outside the release repository.

The supported application exports are implemented and checked above. Independent human reference reviews, unavailable earlier custody, an expert's legal opinion/signature and optional external timestamp/provider acceptance are not generated by this software and are not represented as complete. `manifest.json`, `expert-support.json` and the readable report state each of the four parts as complete or incomplete for that export, and the download shows the same list with its size. The marker reads `complete_expert_packet` only when all four hold: every recorded decision is present and every changed payment has its record, every source file has a custody report and the audit chain links, every statement's stages are recorded, an independently reviewed measurement is linked, and at least one saved tracing calculation recalculates. Otherwise it reads `incomplete_expert_packet`.
